# Web-API-Poster

Вебзастосунок, що публікує одне відео на кілька соцмереж. На сайти він заходить через браузер Microsoft Edge (автоматизація Playwright), а в Telegram публікує через офіційний Bot API.

- Інтерфейс українською й російською (перемикач **UK / RU** угорі праворуч).
- На кожній площадці можна мати кілька акаунтів, у кожного свій профіль Edge.
- Паролі **не зберігаються**. Ви один раз входите вручну, і постер зберігає файл сесії з ключами площадки.
- Ви пишете один шаблон тексту, а AI (OpenAI або Claude) або проста обрізка під ліміти підганяє його під кожну площадку.
- Є черга, відкладені публікації, режим dry-run і debug-файли на випадок помилок.

**Площадки:** YouTube (звичайні відео й Shorts), Telegram-канал, TikTok, Instagram Reels, Facebook Reels, X (Twitter), Threads, Bluesky, Pinterest, Rumble, Dailymotion, Vimeo, Snapchat Spotlight, Likee, VK Видео.

> Сайти часто змінюють інтерфейс, а реальні публікації на них автор коду не перевіряв (не було залогінених акаунтів). Тому **кожну площадку спочатку проганяйте в dry-run**. Якщо крок не знаходить кнопку, надішліть debug-файли (розділ 8): селектори правляться за кілька хвилин.

## 1. Встановлення (Windows 10)

Усі команди нижче виконуються в **PowerShell** (Пуск, набрати `PowerShell`).

### Python 3.12

1. Завантажте Python 3.12 з <https://www.python.org/downloads/windows/>.
2. Під час встановлення обов'язково поставте галочку **«Add python.exe to PATH»**.
3. Перевірте:

```powershell
python --version
```

### ffmpeg (для перевірки відео)

Найпростіше встановити через winget:

```powershell
winget install Gyan.FFmpeg
```

Після цього закрийте й заново відкрийте PowerShell і перевірте:

```powershell
ffprobe -version
```

Якщо winget немає: завантажте архів «release essentials» з <https://www.gyan.dev/ffmpeg/builds/>, розпакуйте, наприклад, у `C:\ffmpeg` і додайте `C:\ffmpeg\bin` у змінну середовища PATH.

Без ffmpeg застосунок теж працює, але не зможе попереджати, що відео не підходить під ліміти площадки.

### Microsoft Edge

У Windows 10 Edge уже встановлений, тож `playwright install msedge` запускати **не потрібно**.

Якщо хочете замість Edge використовувати вбудований Chromium, після першого запуску виконайте:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

## 2. Запуск

Перейдіть у папку проєкту й запустіть скрипт:

```powershell
cd C:\шлях\до\Web-API-Poster
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт сам створить віртуальне середовище `.venv`, встановить залежності, створить `.env` з `.env.example` і запустить сервер. Потім відкрийте <http://127.0.0.1:8000>.

Те саме можна зробити вручну:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Щоб зупинити сервер, натисніть `Ctrl+C`.

## 3. Перший запуск: вхід у площадки

1. Відкрийте сторінку **«Акаунти»**.
2. Додайте акаунт: виберіть площадку й вкажіть назву, наприклад «Рецепти». Для кожного каналу додається окремий акаунт.
3. Поки вхід не виконано, угорі висить жовтий банер «Потрібно увійти в акаунти».
4. Натисніть **«Увійти»**. Відкриється вікно Edge зі сторінкою входу. Увійдіть вручну (пароль, 2FA, вибір каналу). Щойно вхід вдасться, вікно закриється саме.
5. Постер збереже:
   - профіль браузера: `data/profiles/<площадка>/<акаунт>/`;
   - **файл сесії з ключами**: `data/sessions/<площадка>/<акаунт>.json` (cookies і localStorage).
6. Кнопка **«Перевірити вхід»** показує, чи сесія ще жива.

> ⚠️ Файл сесії дає такий самий доступ, як пароль. Нікому його не пересилайте. Уся папка `data/` виключена з git.

**YouTube:** у Google-акаунта вже має бути створений канал. Якщо каналів кілька, виберіть потрібний під час входу: кожен акаунт у постері — окремий профіль.

### Telegram-канал

1. Створіть бота в [@BotFather](https://t.me/BotFather) і скопіюйте токен.
2. Додайте бота в канал **адміністратором** з правом публікації.
3. На сторінці «Акаунти» виберіть Telegram і вкажіть токен та `@username` каналу (або числовий ID `-100…`).

Токен зберігається лише в локальній базі `data/app.db`, а в інтерфейсі видно тільки маску. Обмеження Bot API: відео до **50 МБ**.

## 4. Публікація (спочатку в dry-run!)

1. Відкрийте **«Нова публікація»** й завантажте відео. Воно зберігається в `data/media/` і заливається **як є**, без конвертації.
2. Заповніть назву, опис, хештеги й категорію.
3. Позначте акаунти. Постер одразу перевірить відео під ліміти вибраних площадок і покаже попередження. Публікацію вони не блокують.
4. У блоці **«Тексти для площадок»** натисніть **«Адаптувати під площадки»** і за потреби поправте текст для кожної площадки.
5. Виберіть «Опублікувати зараз» або дату й час (часовий пояс задається в налаштуваннях, за замовчуванням Europe/Kyiv).
6. Залиште галочку **Dry-run** для першої перевірки: постер пройде весь шлях (завантажить відео, заповнить поля), але **не натисне** фінальну кнопку «Опублікувати».
7. Стан завдань дивіться на сторінці **«Публікації»**: Очікує → Виконується → Опубліковано / Помилка / Потребує дії. Там же є кнопки «Повторити» й «Скасувати».

Під час dry-run на YouTube у Studio залишається неопублікована чернетка. Її можна видалити вручну. У Telegram dry-run лише перевіряє токен і доступ до каналу, нічого не надсилаючи.

Завдання виконуються **по черзі**, з випадковими паузами між діями й між публікаціями. Ліміт публікацій на акаунт за добу задається в налаштуваннях. Відкладені публікації зберігаються в базі й переживають перезапуск.

| Telegram | Токен бота й @канал (без браузера) | Перевіряє токен і доступ до каналу | Відео до 50 МБ |
| TikTok | tiktok.com | Завантажує, пише підпис, чекає активної кнопки «Опублікувати» | Посилання на пост не повертається |
| Instagram Reels | instagram.com | Проходить «Створити → Далі → Далі», пише підпис | До 5 хештегів |

| Pinterest | pinterest.com | Заповнює назву й опис | Дошка: та, яку Pinterest вибрав сам, або перша в списку |

Якщо завдання завершилось помилкою «Немає з'єднання із сайтом», перевірте інтернет. Якщо сайт заблокований у вашій країні, увімкніть VPN.

## 6. Капча, 2FA, видимий і прихований режим

- **Видимий режим** (за замовчуванням): якщо сайт просить вхід, капчу чи 2FA, завдання переходить у стан «Потребує дії», а на сторінці «Публікації» з'являється банер. Пройдіть перевірку у відкритому вікні, і постер продовжить сам. Час очікування задається в налаштуваннях.
- **Прихований режим (headless)** вмикається в налаштуваннях. Пройти перевірку в ньому неможливо, тому завдання завершиться помилкою зі скріншотом. Вимкніть прихований режим і натисніть «Увійти» для потрібного акаунта.

## 7. Налаштування

Сторінка **«Налаштування»**:

| Параметр | Що означає | За замовчуванням |
|---|---|---|
| Провайдер AI | Без AI, OpenAI або Anthropic (Claude) | Без AI |
| API-ключ / Модель | Ключ із кабінету провайдера (показується лише маскою); назва моделі | gpt-4.1-mini / claude-haiku-5-5 |
| Браузер | `msedge` (Edge) або `chrome`; якщо його немає, використовується Chromium | msedge |
| Прихований режим | Браузер працює без вікна (капчу пройти не вийде) | вимкнено |
| Скільки хвилин чекати на вхід / капчу | Скільки постер чекає, поки ви пройдете перевірку | 10 |
| Пауза між діями, с | Випадкова пауза між кліками (людиноподібна поведінка) | 1.5–4 |
| Dry-run за замовчуванням | Чи стоїть галочка Dry-run у новій публікації | увімкнено |
| Часовий пояс | Для відкладених публікацій, наприклад `Europe/Kyiv` | Europe/Kyiv |
| Ліміт публікацій на акаунт за добу | Понад ліміт завдання переноситься (0 = без ліміту) | 5 |
| Пауза між публікаціями, с | Випадкова пауза між завданнями черги | 20–60 |
| Категорії | Список для поля «Категорія» (AI враховує її в стилі тексту) | Рецепти, Новини, Музика, Інше |

Ті самі значення за замовчуванням можна задати у файлі `.env` (приклад у `.env.example`). Значення зі сторінки «Налаштування» мають пріоритет.

**AI-адаптація.** Виберіть провайдера, вставте API-ключ і за потреби змініть модель. Якщо AI не налаштований або не відповів, тексти просто обрізаються під ліміти площадки, а зайві хештеги відкидаються.

Ліміти й правила площадок лежать у файлі `platforms.yaml`. Їх можна правити без зміни коду. Значення, у яких джерела розходяться, позначені коментарем `# verify`.

## 8. Якщо щось не працює: debug-файли

Під час будь-якої помилки зберігається папка `data/debug/<номер завдання>/` з трьома файлами:

- `screenshot.png` — знімок сторінки;
- `page.html` — HTML сторінки;
- `steps.log` — лог кроків.

Шлях до папки й посилання на файли видно на сторінці «Публікації». Надішліть ці файли розробнику: найчастіше сайт просто змінив інтерфейс, і треба поправити селектори. Усі селектори зібрані на початку файлу адаптера, наприклад `app/publishers/youtube.py`. Значення, у яких автор не впевнений, позначені `# verify`.

## 9. Тести

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Тести не потребують інтернету й акаунтів: вони перевіряють адаптацію тексту (із замоканим AI), обрізку, перевірку відео, чергу й статуси, планувальник, адаптер Telegram (із замоканим API), визначення входу в кожному адаптері й сторінки інтерфейсу обома мовами. Два тести спільних кроків браузера запускаються лише тоді, коли Playwright може відкрити Chromium.

## 10. Перенесення на Linux-сервер

- Шляхи в коді не прив'язані до Windows. Налаштування беруться з `.env`.
- Edge на сервері зазвичай немає, тому використовується Chromium: `python -m playwright install chromium` або шлях до браузера в `BROWSER_EXECUTABLE` у `.env`.
- Щоб не входити знову, скопіюйте `data/sessions/`. Якщо профіль порожній, постер підвантажить cookies з файлу сесії.
- На сервері без екрана увімкніть прихований режим (`HEADLESS=1`).

## Структура

```
app/
  main.py            запуск FastAPI, воркера й планувальника
  web.py             сторінки й HTMX-фрагменти
  i18n.py            переклади uk / ru
  worker.py          черга завдань, вхід в акаунти
  scheduler.py       відкладені публікації (APScheduler)
  browser.py         Edge / Chromium, профілі, файли сесій, debug
  video.py           перевірка відео через ffprobe
  texts.py           AI-адаптація тексту й обрізка
  publishers/        адаптери площадок: base.py (спільні кроки) + файл на кожну площадку
  templates/         HTML-шаблони
platforms.yaml       ліміти площадок
data/                профілі, сесії, медіа, база, debug (не в git)
```
